# 주민 편지 — 0.6.16 초안

활동 결과 우편에서 `주민 편지 쓰기 · AI 사용`을 누르면 발신 주민의 공방 설정, 그 주민이 아는 활성 기억, 확정된 활동 결과 및 활성 세계 지침으로 편지를 요청한다. 설정 → 관리의 AI 모델 연결에서 편지용 연결을 별도로 선택한다. 편지는 활동 결과와 별도 우편이며 원래 결과를 바꾸지 않는다. 한 활동당 한 편이며 이후 다시 누르면 작성된 편지를 연다.

서버는 같은 활동의 동시 요청을 합치고 결과는 내부 전용 명령으로 저장한다. 활동이 진행 중이면 완료 보고용 우편 공간 한 칸을 예약해 편지 생성이 마지막 자리를 차지하지 않게 한다. 모델 실패나 잘못된 JSON은 저장하지 않는다. 모델 호출 중 세계 revision이 바뀌면 저장을 거부하고 재시도하도록 한다. 편지 읽음과 보관은 기존 우편 명령을 사용한다. 기존 세계 백업에 편지가 포함된다. JSON 형식과 인지 범위 검사는 모델이 허구를 만들지 않음을 보장하지 않는다.

검증: 선택 연결 전달, 누락된 연결 실패, 모델 오류 시 원래 활동·편지·재화 보존, 중복 요청 1회 호출, 내부 명령의 외부 실행 거부, 편지 백업/복원, 기억 필터, 잘못된 응답 거부를 회귀로 검사했다. 우편함의 작성 버튼과 세 연결 설정을 Chromium 픽스처에서 검사했다. 16개 회귀, 엄격 타입, format/lint, 카탈로그와 ZIP 검사를 통과했다. 격리 엔진 2.5.1의 320px 화면에서 편지 모델 선택을 확인했다.

남은 제한: 기존 우편 200건과 완료 활동 100건 상한은 그대로다. 생성 편지는 우편 1건을 추가로 차지하므로 한도에 빨리 도달할 수 있다. 데이터 삭제 없이 별도 기록 저장·조회·백업을 설계하고 마이그레이션해야 한다. 실제 모델의 문장 품질·사실성·비용·지연, 정상 카탈로그 설치 및 실제 Android는 검증하지 않았다. 이 초안은 장기 우편 시스템의 완성이 아니다.

## 기록 분리 저장 기초

별도 `fw-history` 문서에 활동·우편 기록을 불변 스냅샷으로 저장하는 저장소와 중복·충돌·세계 격리·트랜잭션 롤백 검사를 추가했다. 실제 세계 정산·우편 읽음/보관·백업/복원에는 아직 연결하지 않았으며 100/200 한도도 그대로다. 현재 Engine 문서 API는 종류 전체 목록을 불러와 세계별로 거르므로 대규모 페이지 조회 성능을 보장하지 않는다. 활성 기록 이관, 읽음 상태 변경, 백업 정합성, 조회 API와 cursor 성능 검증이 완료된 후에만 한도를 변경해야 한다.
