## 0. 범위: P4를 두 번에 나눈다

P4a(이번): 탐사 → 이야기 탐험, 장면 생성과 읽기(선택지 1회 포함), 장면 문서 저장, 주민별 기억 원장, 관계 · 신뢰 변화, 백업 포함.
P4b(다음): 조사 · 순찰, 편지와 우편함(02-3), 기억 관리 화면(05-1, 정정 · 무효화 · 요약), AI 지침 관리(04-3), 자동 읽기 설정.
이 자리들은 화면에서 "준비 중 · P4b"로 잠가 두었다.

## 1. 구현 범위

| 계획서 | 구현 |
|---|---|
| §7.3 아크와 계획 | 페어마다 3편 묶음 아크. 장소 · 편 제목 · 사건 골격(beat) · 등장 · 시간(30/60/90분) · 준비물(최대 2종) · 관계 변화 상한이 콘텐츠의 저장된 계획이다. 장면의 세부 대사는 열람 때 쓴다. 아크 3종(숲길에 남은 흔적 · 등불 시장의 밤 · 비 오는 날의 공방), 끝낸 아크는 빼고 해시로 다음 아크를 고른다. 사건 골격은 서버에만 있고 화면에는 조건과 발견 종류만 보낸다 |
| §7.3 조건 | 1편은 주민 1명(리드: 페어 중 먼저 공방에 온 주민)으로 출발. 2 · 3편은 두 주민 모두 영입 + 앞 편 읽음. 보관한 페어는 새로 시작하지 않음. 탐험 슬롯 1개. 상태 locked/available는 저장하지 않고 조건에서 매번 계산 → 화면과 명령이 늘 같다 |
| §7.3 출발 · 취소 | 준비물은 사용 가능한 재고에서만(보호분 제외), 출발 때 소모. 배치된 참여 주민은 시설에서 빠지고 시설은 기본 효율로 계속, 진행 중인 회차는 시작 때 속도로 끝난다(아무것도 취소하지 않음). 탐험 중인 주민은 배치 불가. 취소는 준비물 전액 반환, 진행 시간은 초기화 |
| §7.6 72시간 | 탐험 타이머는 작업 시간(simMs)으로 흐른다 → 부재 72시간 상한을 그대로 따르고, 경계에서 멈춘 탐험은 남은 시간을 보존. 시간이 되면 그 즉시 "이야기 열림"(unlocked) 확정. 다음 편 자동 출발 없음 |
| §7.3 · §7.4 생성 | 처음 열 때 언어 모델이 장면을 쓴다(`POST /stories/generate`). 같은 장면 요청이 겹치면 모델 호출 1번을 함께 기다린다. 한 번 저장된 장면은 다시 쓰지 않는다(`fw-story` 문서, 불변). 거절 · 실패면 아무것도 저장하지 않고, 같은 계획으로 다시 시도(재탐험 · 재비용 없음). 트랜잭션 안에서 모델을 기다리지 않는다 |
| §7.7 문맥 | 장면 프롬프트에는 **등장 주민 모두가 아는 기억 + 공개 기억만** 넣는다(`sharedBy`). 한 주민만 아는 기억(A–C에서 생긴 일, 플레이어가 A에게 한 대답)은 A–B 장면에 들어가지 않는다. 필터는 조립 전에 적용하고, 합친 목록에서 지우는 방식은 쓰지 않는다. 원본 카드 글은 `<source_notes>` 안의 자료로만 넣고, 그 안의 지시는 따르지 않는다고 규칙에 적는다. contextManifest(참여자 · 사용한 기억 ID · 프롬프트 버전 · 모델 · 추정 토큰 · 세계 revision)를 장면 문서에 저장한다(본문 원문은 넣지 않음) |
| §7.7 토큰 | 입력 예산 = min(컨텍스트 60%, 컨텍스트 − 출력 예약), 미상이면 6,000. `fitContext`가 잘라내야 하면 생성을 거절하고 큰 컨텍스트 연결을 안내한다(규칙을 몰래 빼지 않음) |
| §7.4 출력 검사 | JSON만 받는다. 등장 주민이 아닌 화자 · 질문자, HTML 꺼쇠, 블록 수(4–16) · 길이 초과, 선택지 2개 이상, 장면 밖 주민이 아는 기억이면 발행 거절. 감정 값이 목록 밖이면 "none"으로 바꾼다. 형식이 깨진 기억 한 줄은 버리고 장면은 살린다 |
| §3 선택지 | 주민이 플레이어에게 묻는 질문 0–1개, 대답 2–3개. 대답은 한 번만. 묻은 주민의 신뢰 +1, 그 대답은 묻은 주민만 아는 기억으로 남는다. 다시 읽을 때는 대답할 수 없다 |
| §7.1 · §7.3 읽음 | "다 읽음"에서 한 번: 장면의 기억을 그 자리에 있던 주민에게 기록, 페어 값은 계획의 상한만큼(편당 각 축 최대 1, 1편은 변화 없음), 최근 사건 = 편 제목. 다시 읽어도 변화 없음. 3편을 다 읽으면 아크가 "읽은 이야기"로 옮겨 가고 다시 읽을 수 있다(도감) |
| §6 저장 · 백업 | 세계 schemaVersion 7(v6에서 순차: 이야기 진행 비어 있음, 기억 비어 있음, 신뢰 0). 기억 원장은 세계 문서 안(읽음과 같은 트랜잭션, 최대 1,000줄, ponytail 주석). 장면 본문은 별도 `fw-story` 문서. 백업 형식 3이 장면 문서를 담고, 복원 때 새 세계 ID로 다시 만든다(형식 1 · 2도 계속 읽음) |

새 명령: `stories.depart`, `stories.cancel`, `stories.choose`, `stories.markRead`.
새 라우트: `GET /stories`(페어별 아크 · 편 상태 · 조건 · 참여자, 서버 계산), `GET /stories/:storyId`, `POST /stories/generate`.

## 4. 결정 사항

- **주민별 사적 기억은 장면 프롬프트에 넣지 않는다.** 계획서 §7.7은 화자별 관점 묶음을 따로 쓰고 결정적으로 조립하라고 한다. P4a는 그 대신 모두가 아는 것만 넣는 보수적인 방식이다. 연속성은 조금 줄지만 유출 경로는 없다. 화자별 분리 생성은 기억 관리(P4b)와 함께 검토한다.
- 아크 계획은 언어 모델이 아니라 콘텐츠의 계획을 쓴다. 저장된 계획 · 조건 · 관계 상한이 늘 같고, 모델 실패가 출발이나 해금을 막지 않는다.
- 목업의 "출발 방식" 라디오(현재 작업 종료 후 출발 / 다른 주민 선택)는 만들지 않았다. 회차 속도가 시작 때 고정되므로 "출발하면 시설에서 빠지고, 진행 중인 작업은 그대로"와 동작이 같다. 페어 이야기는 참여자가 정해져 있다. 같은 내용을 안내 문구로 보여 준다.
- 감정 기호는 P5의 합의된 6종 그림 전까지 글자 기호(♪ ~ ! ? … ✿)로 둔다.
- 기억 원장은 세계 문서 안에 둔다(읽음과 같은 트랜잭션). 1,000줄 상한, ponytail 주석에 별도 문서로 옮길 시점을 적었다.
- 생성은 한 번의 요청이다(엔진의 에이전트 호출 시간 제한 안). 끊기면 같은 계획으로 다시 시도한다(ponytail 주석).

## 5. 미검증

- 실제 언어 모델(Claude, GPT 등)이 계약에 맞는 장면을 얼마나 자주 내는지, 글의 품질과 말투 유지. 시험용 서버의 정해진 답만 확인했다.
- 자연어 수준의 모순 · 지식 유출률(계획서 §11 평가 corpus): 측정하지 않았다. 구조적으로 막은 것은 "공유하지 않은 기억을 프롬프트에 넣지 않음"과 "장면 밖 주민이 아는 기억 거절"뿐이다.
- 엔진 재시작 · 연결 변경 중 생성 중단, 여러 탭에서 동시에 읽기.
- 실제 Android 기기, 재미 · 부담(탐험 시간 · 준비물 균형), 성능 수치.
