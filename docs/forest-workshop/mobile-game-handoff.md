# 숲결 공방 모바일 게임 UI·UX 인수인계

기준: 2026-10-28, main 2211a07ea, 0.6.6. 작업 시작 시 두 저장소 원격과 설치 버전을 다시 확인한다. 목표는 출시된 상업게임의 실제 플레이 화면과 조작 흐름을 근거로 공방을 개선하는 것이다. 사용자 데이터와 기존 기능을 보존한다.

## 참조와 확인 범위

- 재배소년 탐험: https://tsuya00.tistory.com/3436 의 실제 지도·목록·상세 화면. 장소, 참여자, 시간, 조건, 상태, 출발 행동의 연결을 참고한다.
- 놀러와 마이홈 의뢰게시판: https://hanfanc.tistory.com/323 의 실제 카드·선택 상세 화면. 요구 물품과 수량, 보상, 실행 행동을 함께 파악하는 구조를 참고한다.
- 홈·제작, 프로필, 이야기의 연속된 실제 플레이 화면은 추가로 조사한다. 원본을 직접 조작하지 않았고 일부 자료는 이전 버전이므로 추측을 관찰 사실로 기록하지 않는다. 상세 참조 및 한계는 game-ui-reference-2026-10-28.md에 있다.

## 요구사항과 순서

1. 기존 요구사항을 완료·부분 완료·누락·후퇴로 분류하고 각 원본 화면, 공방 화면, 조작 횟수와 차이를 기록한다. 기존 기능 삭제 여부는 Git 이력과 실제 실행을 대조한다.
2. 격리된 ME-personal 엔진에서 실제 아트와 데이터를 표시하는 테스트 서버를 띄우고 변경 전 홈→제작·채집→의뢰→탐험→이야기→기록을 조작해 스크린샷과 스크롤, 터치 횟수를 기록한다.
3. 기준 게임의 화면 구성과 동선을 적용한다. 홈에서 시설·작업 상태에 접근하고, 제작품 변경·재고 보호·판매·시설 강화의 진입을 가까이 둔다. 탐험은 참여자·조건·시간·상태·행동을 함께, 의뢰는 선택한 요청의 재료·보호량·보상·납품을 함께 표시한다.
4. 홈 주민이 좌우·상하로 움직이며 서로 다가가고 인사하는 생활 연출을 만든다. 이름표는 숨기고 프로필과 기존 페어 이야기로 연결한다. 생활 연출만으로 기억이나 관계를 바꾸지 않는다. 지면 이동영역과 장애물을 직접 편집하고 저장·취소·기본값 복원 및 백업 호환을 제공한다.
5. 프로필의 그림·활동·관계·기록을 정리하고 원본 설정과 편집 초안을 보존한다. 이야기창 크기를 안정화하고 감정표현을 그림 기준점에 맞추며, 읽은 이야기의 재접속·백업 복원을 검증한다.
6. 주민초대 탭에 중복된 종표교환 카드는 제거하되 별도 교환 탭은 유지한다. 전체화면 버튼은 제거하고 가용 화면을 채운다. 브라우저 전체화면 자동 진입은 플랫폼 제한을 확인하고 허용된 진입 동작에서만 요청한다.
7. 주아체의 사용 조건을 확인해 로컬 번들에 적용하고 라이선스를 포함한다. 버튼·패널·탭·상태·폰트의 일관성과 가독성을 정상 아트로 검증한다.

## 재점검과 검증

- 화면 DOM 전체 교체 시 입력·포커스·스크롤·주민 움직임이 유지되는지 점검한다. 납품 조회 중 세계 전환 시 이전 세계 응답이 반영되지 않게 검사한다.
- 320×640, 360×800, 390×740, 큰 글자, 긴 대사, 키보드, 빈 상태, 부족·잠금·진행·완료·오류를 실제 렌더링에서 조작한다. 주요 행동을 페이지 스크롤 없이 이용할 수 있게 한다.
- 이야기 마지막 장면과 기록, 재접속·업데이트·백업 복원, 보호 재고와 중복 납품, 세계 전환, UTC 날짜 변경, 오프라인 복귀 및 30분 홈 실행을 확인한다.
- 기존 회귀 테스트, 브라우저 테스트, 엄격 타입 검사, format/lint, 카탈로그·ZIP 해시 및 격리된 실제 설치·업데이트를 수행한다. Android 기기 검증과 브라우저 검증을 구분한다.
- 새 공개 버전으로 소스에서 번들·카탈로그를 재생성하고 변경 전후 스크린샷과 미검증 항목을 PR에 명시한다. 실제 원본 자료와 완성 화면을 비교하기 전 완료를 선언하지 않는다.

## 작업 기록 — 2026-10-28

격리 엔진 2.5.1 (`b8bf28382b740cac77f310df442f98c493166f43`)과 0.6.6 fixture로 390×740에서 공방 생성·주민 등록·홈 진입을 수행했다. 홈은 엔진 상단 바 아래 표시되었고 내부 전체화면 버튼이 장면 위에 나타났다. 0.6.7 fixture로 재시작한 화면은 [홈 화면](mobile-review/home-390-after.png)이다. 이는 엔진의 정상 카탈로그 설치나 Android 실기기 검증이 아니다.

현재 변경: 초대의 중복 종표교환 카드와 홈 전체화면 버튼 제거. 납품 목록은 다른 세계나 더 최근 요청으로 전환된 뒤 도착한 응답을 무시한다. 엔진 상단 바 제거·진입 시 전체화면, 지면·주민 상호작용, 프로필, 제작·탐험·의뢰 디자인과 실제 기준 게임 화면 비교는 미완료다. 이 변경으로 전체 계획이 완료된 것은 아니다.

### 작업 화면 관찰

갱신한 0.6.7 ZIP을 fixture로 주입한 엔진의 390×740 화면에서 하단 작업 메뉴로 진입했다. [현재 작업 화면](mobile-review/work-390-current.png)에는 채집·재배·조사·가공·제작, 세 작업 탭, 시설 강화·주민 배치, 현재 작업이 보인다. 세로 공간 대부분을 탭과 시설 정보가 차지하며 재고 보호·판매가 직접 보이지 않는다. 홈의 진행 작업 바로가기는 테스트 세계에서 새 작업 보고가 우선 표시되어 이번 실엔진 시험에서 확인하지 못했다. 시설 상세 연결 역시 실엔진에서 확인하지 못했다. 화면은 기기 실측이나 사용성 평가가 아니다.

### 재고 관리 진입 시안 검증

작업 상태 카드에 재고 보호와 창고·판매 버튼을 추가한 시안을 390×740 Chromium 픽스처로 시험했다. 작업 영역 높이가 659px인데 콘텐츠가 711px이 되어 기존 화면 맞춤 검사가 실패했다. 두 버튼을 그대로 추가하면 주요 작업 화면에 스크롤이 생기므로 시안을 되돌렸다. 되돌린 뒤 같은 브라우저 회귀 검사는 통과했다. 다음 구현에서는 기존 시설·탭·정보의 배치를 실제 기준 게임과 비교해 재구성해야 하며, 버튼을 추가하는 것만으로 접근성을 해결했다고 판단하지 않는다. 실제 아트·엔진 화면과 작은 320px 화면은 이 시안에서 검증하지 않았다.

### 재고 관리 재배치 후 검증

작업 상태에 재고 보호와 창고·판매 진입을 추가하고, 평상시 반복 안내를 제거하며 카드 간격을 줄였다. 보호 재고 조건이 발생하면 기존 부족 안내는 유지한다. 브라우저 픽스처의 390×740 화면 높이와 두 버튼의 이동 대상 검사는 통과했다. 격리 엔진 2.5.1과 ZIP fixture에서 [390×740 화면](mobile-review/work-stock-390.png)을 직접 확인했다. [320×640 화면](mobile-review/work-stock-320.png)에서는 시설 설명과 상단 영역 때문에 버튼이 아래로 밀려 스크롤이 필요하다. 해당 크기에서 스크롤해 재고 보호를 누르면 보호 탭으로 이동했다. Android 기기와 정상 카탈로그 설치는 미검증이다. 320×640 한 화면 목표는 미완료다.

### 화면 정렬 참고와 검증

Apple의 [게임 디자인 지침](https://developer.apple.com/design/human-interface-guidelines/designing-for-games/)과 [휴대용 게임 인터페이스 발표](https://developer.apple.com/videos/play/meet-with-apple/243/)는 읽기 쉬운 글자, 충분한 터치 영역과 다양한 화면 크기 대응을 강조한다. [놀러와 마이홈 공식 도움말](https://sites.google.com/skywalkgames.com/welcomemyhomekr/faq/%EA%B2%8C%EC%9E%84-%EA%B8%B0%ED%83%80)은 제작 도구를 누른 뒤 하단 제작 목록에서 물품을 선택하는 맥락을 설명한다. 이전 게임 플레이 캡처 분석은 game-ui-reference-2026-10-28.md에 있다. 이 자료만으로 제작 화면 전체 조작을 직접 확인했다고 주장하지 않는다.

아트 CSS의 시설 버튼 자동 왼쪽 여백을 작업 화면에서 없애고 시설·재고 버튼을 중앙 정렬했다. 시설 설명 전문은 시설 상세에서 유지하고 작업 화면은 속도와 주민 상태에 집중한다. 320×640 엔진 [확인 화면](mobile-review/work-align-320-before-final.png)에서 하단 항목이 여전히 화면 밖이었고 배치 변경 글자가 두 줄로 나뉘어 글자 크기를 추가 조정했다. 이 이미지는 마지막 글자 크기 조정 이전이며 그 변경의 실엔진 검증은 아직 하지 않았다. 작업 화면 픽스처와 카탈로그 검증은 최종 변경 후 통과했다. 실제 Android 기기와 확대 글자 검증은 미완료다.

### 0.6.7 호환·회귀 재검증

기준 PR 브랜치 `998e72159`, 엔진 2.5.1 `b8bf28382b740cac77f310df442f98c493166f43` (번들의 기준 엔진 `7f341f9186db8e08f21d63cc47ec458deff250d5`). manifest 범위는 2.5.1 이상 4.0.0 미만이며 실제 실행 검증은 이 엔진에 한정한다. ZIP SHA-256 `08f704f247a420c3a71ef71cd6786d6c5cd1e901ccedec1c682fc9ff999c4b12`가 로컬 카탈로그와 일치하고 fixture 주입 후 엔진 health에서 활성·준비 완료를 확인했다. 정상 카탈로그 설치와 실제 기기 시험이 아니다.

엄격 타입 검사, 서버 회귀 9개, 브라우저 회귀 11개, format/lint, 카탈로그 lane·locale·해시·릴리스 노트 검증이 통과했다. 최종 번들의 [320×640](mobile-review/work-verified-320.png)과 [390×740](mobile-review/work-verified-390.png)을 격리 엔진에서 확인했다. 320×640은 여전히 주요 작업과 재고 버튼이 화면 밖으로 밀려 스크롤이 필요하며, 스크롤 후 재고 보호 탭 이동을 확인했다. 390×740에서는 작업과 두 재고 버튼이 보인다. Android 설치형 웹앱, 일반 카탈로그 설치 및 기존 사용자 데이터 업데이트는 미검증이다.

### 작업 화면 구조 재배치

현재 작업을 먼저 표시하고 분야 탭과 시설 그림을 축소했다. 운영 방식은 제작 설정·순서 화면에서 변경하고, 처리 속도의 상세는 시설 화면에서 확인한다. 작업 진행 정보가 작은 화면에서 전체 열을 차지하던 CSS 충돌을 수정했다. 버튼 최소 높이는 44px을 유지한다.

작업 화면 픽스처에 320×640 세로 넘침 검사를 추가했고 390×740 검사와 함께 통과했다. 엄격 타입 및 format/lint 검사도 통과했다. 격리 엔진에서 최종 번들의 [320×640](mobile-review/work-compact-320.png), [390×740](mobile-review/work-compact-390.png)을 확인했다. 목표 재고를 채워 쉬는 상태에서 두 화면 모두 현재 작업·강화·배치·재고 보호·판매가 최초 화면에 표시됐고 재고 보호 이동이 성공했다. 320px의 판매 버튼 위치는 y=515.09px, 높이=44px이다. 320px에서 하단 추천 설정까지 한 화면에 모두 들어오는 것은 아니다. 진행 중 작업·장문 주민 이름·큰 글자와 모든 상태의 실엔진 검증은 남아 있다. 정상 카탈로그 설치나 Android 실기기 검증으로 간주하지 않는다.
