# 조사·순찰 — 0.6.13

우편함 PR #16 위의 후속 구현이다. 공방 주변 한 장소에서 조사 30분 또는 순찰 15분을 영입 주민 1명이 진행한다. 세계당 동시 활동 1개이며 이야기 탐험 중인 주민은 참여할 수 없다. 출발 시 시설 배치에서 빠지고 진행 중 생산 작업은 유지한다. 활동 중 시설 재배치와 같은 주민의 이야기 탐험 출발도 서버에서 거부한다. 취소해도 재화는 소모되지 않으며 이전 시설에 자동 재배치하지 않는다.

시간은 기존 공방 simMs와 creditTime의 72시간 상한을 사용한다. 완료 시 기록과 고정 결과 편지가 같은 세계 저장에 반영된다. 이벤트 ID와 완료 기록으로 중복을 막는다. 재료·골드·초대권 보상, 생성 모델 호출, 기억 원장 자동 추가는 없다. 결과는 사실 범위가 고정된 짧은 템플릿이며 향후 주민 편지 생성을 붙이기 전 별도 문서 저장과 인지 범위/지침 검증이 필요하다.

schema 10→11에서 비어 있는 활동 상태를 추가한다. 새 형식으로 저장한 세계는 이전 패키지에서 열 수 없다. 완료 기록 상한 100개와 우편 상한 200개에 도달하면 새 출발을 거부하며 기존 기록을 지우지 않는다. 장기 사용을 위해 외부 기록 문서·페이지 조회로 확장해야 하는 초기 제한이다.

검증: 실제 command/settlement service와 FakeHost persistence에서 주민 등록·출발·시설 해제·생산 작업 유지·중복 배정 거부·29분 진행/30분 완료·반복 정산 후 결과 편지 1개·취소·재화 불변·백업 복원을 확인했다. 브라우저 검사에서 조사/순찰 탭·선택 주민·출발 종류·취소·우편함 이동을 확인했다. 엄격 타입·format/lint·회귀 13개·카탈로그 lane/locale/ZIP 해시/릴리스 노트 검사가 통과했다.

격리 엔진 2.5.1에 0.6.13 ZIP fixture를 적용해 주민을 등록하고 [320px 실제 화면](mobile-review/activity-running-engine-320.png)에서 조사 출발·진행 표시·취소 후 출발 화면 복귀를 확인했다. 실제 엔진에서 30분을 기다려 완료한 것은 아니며 완료 시점과 백업은 서버 회귀 환경에서 검사했다. 정상 카탈로그 업데이트·사용자 세계·Android·장시간/모든 상태 레이아웃은 미검증이다.
