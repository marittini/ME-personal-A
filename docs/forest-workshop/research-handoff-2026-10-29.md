# 숲결공방: 주민 경험과 AI 생성 개발 조사·검증 인수인계

작성 2026-10-29. 기준: ME-personal-A 원격 main `0b5904d7cd924b896f9d49842bcc1ffc02171a97` (0.6.14), 엔진 조사 체크아웃 `b8bf28382b740cac77f310df442f98c493166f43`. 엔진 원격 최신 main으로 간주하지 않는다. 이 문서는 조사와 설계 초안이며, 구현·실기기 실험·사용자 조사 결과가 아니다. 별도로 구축된 공방 진입점은 변경 대상이 아니다.

## 사용자 요구와 제품 판단

사용자의 캐릭터가 정지 그림으로 좌우 미끄러지는 현상, 터치 즉시 프로필로 넘어가는 동선, 정형화된 보고서 형태의 우편, 기능별 모델 연결 설정 부재를 해결한다. 목표는 캐릭터의 개성·관계·경험이 플레이에 드러나는 AI 기반 방치형 공방이다. 기능 존재, CSS 애니메이션 유무, 테스트 통과만으로 재미·사용성 향상을 판정하지 않는다.

## 코드에서 직접 확인한 사실

1. `screens/home/home-scene.ts`의 `sceneResidents`는 영입 주민을 정렬해 최대 둘만 표시한다. 주민 터치는 `openResidents`와 프로필 `openSheet`를 즉시 호출한다. 주민을 누른 뒤 반응은 별도 구현되어 있지 않다.
2. `styles-residents.ts`의 `fw-ground-left/right`는 18초 반복으로 left/top을 움직이고 `fw-facing-left/right`는 각각 12초/15초 주기로 방향을 뒤집는다. 서로 다른 주기이므로 이동 방향과 시각적 방향이 어긋날 가능성이 있다. 화면 캡처로 체감 정도를 아직 확인하지 않았다. CSS transform이 상위/하위에 중첩된다. 지면 편집 및 OS 모션 감소 처리는 이미 있다.
3. `resident-figure.ts`는 사용자 제공 단일 이미지를 보여 주며 투명 PNG/정적 WebP를 기반으로 한다. 팔·다리·머리 분리 정보나 실제 걷기 프레임은 없다. 정지 그림을 변형하면 실루엣 움직임은 줄 수 있으나 발이 교대로 움직이는 걷기를 구현한 것은 아니다. 사용자 이미지를 덮어쓰지 않는다.
4. `services/story-service.ts`, `services/rebuild-service.ts`는 각각 `runtime.languageModels.resolve(null)`을 호출한다. 이야기 저장 manifest에는 실제 `connectionId`, `model`, 지침 revision과 선택된 사실 ID가 남는다. 주민 설정 재제안은 초안이며 확정 전 저장하지 않는다.
5. 조사한 엔진의 `packages/shared/src/types/capability-runtime.ts`에서 `CapabilityLanguageModelHost`는 `resolve(connectionId?: string | null)`과 `resolveForRequest({connectionId, chatConnectionId, model})`를 제공하지만 **연결 목록 조회 메서드는 없다**. 엔진의 채팅 설정에는 연결 선택 UI가 있다. 공방 패키지가 안전한 목록 API를 이용할 수 있는지는 아직 확인하지 않았다. 다른 엔진 커밋에서 동일 API가 존재하는지도 타입 검사로 확인해야 한다.
6. `domain/activities.ts`의 정산은 고정 문자열을 결과와 편지에 함께 넣고 발신인을 주민 이름으로 지정한다. 창작된 주민 편지가 아니며, 활동 1건당 동일 eventId로 중복을 방지한다. `domain/model/mailbox.ts`의 현 상한은 편지 200건, 본문 1,000자이고 편지는 세계 문서에 들어간다. 장문 생성·대량 우편을 위한 별도 문서/인덱스/백업은 없다.
7. `domain/model/memory.ts`의 기억은 인지 주민 IDs, 공개 범위, 출처 이야기 등을 가진다. 1,000건 상한이 있다. 세계·페어 지침은 이야기 생성에 쓰이지만 우편 생성은 미구현이다.

## A. 주민의 움직임과 터치: 구현 전 시제품 및 판단

### 목표 행동

- 상태: 대기 → 준비 → 이동(상하 압축·복원) → 도착 → 대기. 이동 방향 변경은 실제 경로 방향과 같은 시점에 발생한다. 터치하면 이동/표현을 안전하게 중단하거나 정지 상태로 전환 → 즉각적인 몸짓과 감정 표시 → 짧은 상호작용을 제공한다.
- 터치 결과 예시(시제품 가설): 주민이 살짝 압축됐다 복원하면서 말풍선에 인사 → 말풍선 또는 간단한 행동 메뉴에서 `대화`, `프로필`을 명시적으로 선택. 매번 팝업이 가리는 것이 편한지, 한 번 더 눌러야 하는 불편과 어떻게 균형을 잡을지는 실제 영상과 사용성 검토로 결정한다. 기존 프로필 경로는 유지한다.
- 우선 **시각 반응은 로컬**로 즉시 표시하고, 생성 대사 요청은 사용자가 선택한 경우에만 시작하는 안을 검토한다. 무반응이나 대기 동안의 터치 중복을 막는다. 임시 문구는 AI 생성이나 주민별 기억이 반영된 것처럼 표시하지 않는다.
- 이동·좌우 반전·몸 변형·감정 표식을 별도 계층으로 적용해 transform 충돌을 피한다. 발 위치 기준점과 그림자, 기존 placement, 지면 범위 및 터치 영역을 보존한다. 감정표식은 주민의 이미지 배치에 맞춰 위치를 계산하고 모션을 따라가게 한다.
- 투명 여백이 큰 그림, 비정형 이미지, 확대/축소·좌우 위치, 그림 없는 주민, 1/2명, 경계와 겹침, 빠른 반복 터치, 재렌더, 백그라운드, 지면 편집, reduced motion을 확인한다. reduced motion에서도 터치 반응의 정보는 보인다.
- 먼저 기존 단일 이미지로 2~3개의 보간·압축 시안을 녹화해 비교한다. 탄성·속도는 실험값이며 특정 수치를 근거 없이 확정하지 않는다. 발이 미끄러져 보이면 실제 걷기처럼 포장하지 말고 추가 프레임/분리 자산 선택지를 제시한다. 이미지 손상·자동 덮어쓰기는 금지한다.

### 완료 근거

동일 주민·동일 위치로 변경 전후 15~30초 화면 녹화, 좌우·상하 이동과 터치 반응 캡처, 가상 모바일 크기별 실제 실행, 반복 터치/지면 회귀를 남긴다. 가능하면 사용자의 실제 Android 확인을 별도로 받고, 감각적 완성도는 인간 평가가 없으면 미확정으로 기록한다.

## B. 기능별 모델 연결: 편지보다 먼저

- 설정의 기능별 항목: 이야기 장면 / 주민 설정 재제안 / 주민 편지. 각 기본값 `엔진 기본 연결`; 지정 연결의 표시 이름과 현재 모델을 식별할 수 있게 한다. 연결 ID는 설정일 뿐 API 키를 저장하거나 백업에 포함하지 않는다. 세계에 저장할지 엔진 로컬 환경 설정에 저장할지는 실제 장치 간 공유·백업·식별자 이동 시나리오를 확인한 뒤 결정한다.
- `resolve(id)`는 확인됐으나 목록 capability는 확인되지 않았다. 엔진이 공개한 인증된 연결 목록 API가 패키지에 사용 가능한지, 응답에 비밀 정보가 없는지, 패키지의 권한 범위와 2.5.1 호환을 먼저 조사한다. 지원이 없다면 엔진 capability 확장을 별도 변경으로 설계한다. 비공개 DB 접근·임의 ID 강요·키 노출로 우회하지 않는다.
- 선택 연결 삭제·비활성·미설정·연결 실패 시 기능과 선택 연결을 알리고 재설정/재시도를 제공한다. 자동 기본 연결 대체는 사용자가 의도한 모델과 비용을 바꿀 수 있으므로 임의로 수행하지 않는다. 설정 변경은 기존에 저장된 이야기·편지를 재생성하지 않는다.
- 단위·통합 시험: 각 기능이 서로 다른 fake connection으로 전달되는지, 기본값·설정 변경·삭제된 ID·provider 오류·권한·동시 요청·백업/복원·비밀키 미포함·실제 사용 manifest 검증. 실제 연결 2개를 이용한 엔진 테스트는 환경이 허용하는 경우 별도 기록한다.

## C. 주민 편지: 실제 사건을 주민의 관점으로 표현

### 플레이 흐름 후보

조사/순찰 결과 확정 → 결과는 즉시 확인 가능 → 플레이어가 `주민 편지 받기`를 선택하거나 명시적으로 설정한 방식으로 생성 → 로딩 및 실패/재시도 표시 → 받은 편지함에서 주민의 편지 확인 → 보관. 자동 모델 호출 여부·빈도는 확정하지 않는다. 결과를 편지 생성 성공 여부와 결합해 잠그지 않는다.

### 사실과 서술 분리

- 활동 `eventId`, 참여자, 활동 종류·완료 시간·실제로 확정된 결과를 서버의 권위 있는 사건으로 둔다. 생성문은 말투와 감상으로 표현하되 미지급 물건, 만나지 않은 주민, 성취, 기억을 사실로 확정하지 않는다. 생성 텍스트를 실행 가능한 게임 명령으로 취급하지 않는다.
- 현재 결과는 '공방 주변을 살펴봄' 정도여서 개인화할 실제 사건이 부족하다. 무작정 글을 길게 늘리면 허구만 늘 수 있다. 장소·관찰·함께한 대상처럼 **실제 엔진이 확정할 수 있는 사건 항목부터** 설계하고, 사실에 없는 내용은 상상/감상임이 드러나도록 한다.
- 프롬프트는 발신 주민의 설정, 그 주민이 아는 관련 활성 기억, 세계 지침, 선택한 관련 사건만 최소화해 전달한다. 타 주민 비공개 기억은 제외하고 기밀·원문 불필요 복제를 피한다. 페어 지침은 편지가 실제 페어 맥락일 때만 적용한다.
- 요청 중복/동시 탭, 생성 중 지침·기억 변경, 재시도, 타임아웃, 부적합 출력, 세계 이동, 저장 실패, 기존 고정 활동 편지와 신규 편지의 ID 관계를 설계한다. 사실 유효성은 구조 검사만으로 완전 보장할 수 없다. 표시 전 검증 및 사람 검토 기준을 둔다.
- 200개 상한에 도달하면 출발 자체가 막히는 현재 구조를 악화시키지 않도록 별도 본문 저장·조회·인덱스·정합성·백업·마이그레이션을 먼저 설계하고, 기존 편지/읽음/보관을 보존한다. 구버전 호환과 롤백 제한을 명시한다.

### AI 평가 시나리오
