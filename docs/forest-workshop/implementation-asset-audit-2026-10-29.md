# 숲결공방 구현·에셋 누락 재조사

2026-10-29. 기준: `marittini/ME-personal-A` 원격 main `0b5904d7cd924b896f9d49842bcc1ffc02171a97`, 설치 번들 0.6.14. 엔진 원격 main은 `7f341f9186db8e08f21d63cc47ec458deff250d5` (2.5.1); 조사한 로컬 엔진 진입점 브랜치 체크아웃은 `b8bf28382b740cac77f310df442f98c493166f43`로 엔진 main과 구분한다. 사용자 제공 `Forest_Workshop_Development_Plan_2026-10-27.md`는 당시 계획이며 완성 보고가 아니다. 이후 사용자의 진입점 별도 구축, 전체화면, 주민 터치 반응 등의 지시가 최신 요구다.

범위: main의 소스, 빌더, 카탈로그, ZIP 및 관련 문서에 대한 정적 조사. 일부 격리 Chromium 픽스처·에셋 해시 검증. 현재 사용자 Android나 실제 사용자 데이터, 정상 카탈로그 설치, 실모델 응답, 원본 전체 목업과의 화면별 비교는 수행하지 않았다. 아래 '미구현'은 조사한 범위에서 관련 기능을 발견하지 못했다는 의미다. 상업적 완성도와 사용성은 코드 존재 여부로 판정하지 않는다.

## 에셋: 파일, 번들, 실제 화면 사용을 구분

### 직접 검증

- `assets/asset-manifest.json`의 이미지 82개, 저장소 WebP 82개, `asset-paths.json`의 WebP 82개를 대조했다. 각 저장소 파일의 SHA-256은 manifest와 모두 일치한다.
- 원격 main에서 추출한 `forest-workshop-0.6.14.zip` 내 82개 이미지도 manifest SHA-256과 모두 일치한다. 레거시/v2/v3 카탈로그는 모두 0.6.14와 동일 ZIP 해시 `12340de83fa4b19976671dcb8e2310729a73373c87eccf0de857bfd07c091008`, 10,168,253 bytes를 가리킨다. Git 객체 기준 확인이며 정상 네트워크 설치 검증이 아니다.
- `assets/CREDITS.md`는 목록에 있으나 ZIP에 없다. 빌더는 `.md`를 의도적으로 제외하며 제작 정보를 저장소에 남기도록 주석을 달았다. 그림 누락이 아니라 배포 문서 미포함이다. 설치물에서 출처를 볼 필요/라이선스 전달 요건은 별도 검토해야 한다.
- 기존 `forest-workshop-assets.regression.ts` 통과. 이 검사는 존재·매핑·해시 등이며 모든 화면에서 올바르게 렌더링됐음을 뜻하지 않는다.

## 기능별 대조: 있음 / 부분 / 누락

### 세계·주민·관계

- 세계 생성·전환·닉네임, 시작 꾸러미, 주민 원본 가져오기, 공방용 프로필과 사진 업로드, 사진 배치 및 이력, 페어 생성·보관·복원은 구현돼 있다. 실제 0.6.14 기존 세계 업데이트·백업 복구는 이번에 확인하지 않았다.
- 주민의 홈 직접 행동, 터치 응답, 시설 사용/휴식/주민 간 상호작용은 부족. 홈 노출은 두 명으로 고정되어 모든 주민 생활을 볼 수 없다.
- 특기 분야·돌파·페어 생산 보너스는 기존 기능. 원본 정체성을 해치지 않는 '랜덤 공방 프로필' 범위와 세트 효과는 원 계획상 검토/선택 항목이며 구현되지 않았다고 바로 확정하지 않는다. 20개 특기·후보 풀별 성과의 최신 30일 비교는 확인되지 않았다.
- 직접 지면 사각형 편집·저장·취소·초기화는 있다. 장애물·다각형·실제 행동과의 충돌·시설 주변 자연스러운 경로는 미완료다.

### 경제·작업·의뢰

- 5개 시설, 조건 해금·업그레이드, 추천/목표 생산, 지정 횟수 대기열, 보호 재고, 수동 판매, 일일 자동 판매가 있다. `continuous` 초과 판매 모드도 현재 코드에 있다. 따라서 단순히 '초과 판매 미구현'으로 적으면 틀리다.
- 2026-10-27의 제한된 30일 생산 기준선과 초과 판매 계산 기록은 있으나, 계획에서 요구한 최신 main 기준 의뢰·티켓·초대·특기·배치·96시간 부재를 포함하는 전 범위 30일 시뮬레이션과 실제 플레이 검증은 확인되지 않았다.
- 원 계획의 '24시간당 의뢰 기회 1개, 미사용 최대 3개, 1장' 정책은 현재 코드와 다르다. 현재는 UTC 날짜마다 의뢰 3개, 기회 이월 없음, 의뢰별 1~3장이다. **계획 대비 미적용이지 현 정책을 임의로 바꾸라는 결론이 아니다**. 마이그레이션과 실제 밸런스를 평가해야 한다.
- 보호·판매·강화는 기능이 있으나 접근 경로가 실제 사용자에게 눈에 띄는지 및 설정/실패/복귀 동선은 기기별 현행 화면에서 다시 검증해야 한다.

### 이야기·관계·AI

- 고정 아크 3개×3편, 편당 탐험 및 읽기 시 생성, 공유 기억, 선택, 이야기 기록, 자동 넘기기 설정은 있다. 저장된 이야기 ID는 50회 이상 별도 namespace를 사용하고, 페어당 완료 아크 및 기억·백업에 한도가 있다. 과거의 50건 삭제 문제와 현재 1,000건 한도를 혼동하지 않는다.
- 원 계획의 '한 번 예약하여 총 3시간 후 아크 진행'은 구현되지 않았다. 현재 편마다 출발·읽기 뒤 다음 편이 열린다. 첫 편 1명·다음 두 편 2명 기존 기능을 보존할 방법을 먼저 설계해야 한다.
- 탐험/활동 출발 시 시설 배치는 해제되며 종료·취소 시 자동 원복은 확인되지 않는다. 활동 구현 문서는 자동 재배치하지 않는다고 명시한다. 사용자에게 영향을 충분히 알리는지 재검수 필요.
- 세계/페어 지침과 기억 관리·정정·중지/복원은 구현됐다. 지침을 용도별(이야기/편지/요약)로 나누고 주민별 지침, 비교·이전 버전 탐색, 생성 편지에 적용하는 전체 목업 범위는 미완료 또는 미확인이다. 기억 검색·출처 이야기 바로가기·정정 이력 전용 탐색도 구현 문서에서 남은 범위다.
- 선택형 AI 장면 삽화 생성·미리보기·수정·갤러리·오류 복구는 확인되지 않는다. 주민 사진 업로드나 배경 에셋을 AI 삽화 생성으로 취급하지 않는다.
- 실제 모델 응답 품질, 캐릭터성, 인지 범위 누출, 반복·지연·실패 복구는 자동 테스트 통과만으로 확인되지 않는다.

### 우편·조사·날씨

- 받은 편지/보관함과 고정 환영 편지, 주민 1명의 공방 주변 조사/순찰, 활동 완료 시 고정 결과와 편지는 있다. 총 기록 100개 또는 우편 200개에 이르면 새 활동 출발을 거부한다. 생성 편지와 별도 본문/커서 저장·장기 보관 설계가 없다.
- 활동 결과의 생산물/재화 보상, 모델 호출, 기억 자동 추가는 현재 없다고 명시돼 있다. 원 계획에서도 초기 고정 결과는 보상 없는 프로토타입이므로 이것만으로 장애라고 단정하지 않는다. 주민 편지와 관계성이라는 사용자 목표에서는 미완성이다.
- 도시 선택·실제 날씨·날씨 효과는 `features.ts`에서 준비 중. 수동/자동 계절 선택은 날씨가 아니라 배경 변경이다.

### 시각·모바일·출시 검증

- 대사 영역 측정·분할, 이야기 자동 넘기기, 일부 감정표시 위치 보정은 구현됐으나 기기·장문·확대 글꼴에서 안정적이라는 증거는 이번에 없다. 프로필 정보/편집 분리도 구현과 디자인 만족은 별개다.
- 이전 스크린샷과 테스트 일부는 특정 구버전 또는 fixture다. 사용자 Android 화면, 설치형 PWA/웹뷰, 전체화면·시스템 바·뒤로가기, 회전·키보드, 긴 이름/200% 글자, 모든 화면의 스크롤과 이미지 로딩, 정상 카탈로그 설치/업데이트 및 사용자 세계 복원은 미검증이다.
- 직접 확인한 이전 자료: 저장소의 `game-ui-reference-2026-10-28.md`에 재배소년 탐험과 놀러와 마이홈 의뢰 게시판 플레이 캡처 분석이 있다. 이전 관찰과 현행 버전·실제 조작은 구분한다. 기존 조사 누락을 인정하고 화면별 재대조에 사용한다.

## 이번에 실행한 검사와 한계

1. remote main fetch, 엔진 main `ls-remote` 확인.
2. main을 `/tmp/forest-audit`에 별도 추출. 메인 작업 브랜치나 사용자 데이터를 수정하지 않음.
3. 82개 이미지의 저장소/ZIP 해시와 카탈로그 세 레인의 버전·ZIP 해시 비교. `CREDITS.md` ZIP 제외는 빌더의 의도적 `.md` 필터로 확인.
4. 격리 390×740 Chromium 홈 모션 테스트와 에셋 회귀 통과. 기존 홈 테스트는 애니메이션 `currentTime`을 직접 0과 9000ms로 옮겨 좌표를 검사하고, 주민 클릭 시 프로필 진입이 현재대로 동작하는지도 검사한다. 즉 자연스러운 모션·무터치 장시간·터치 반응 요구 충족을 입증하지 않는다.
5. 같은 격리 픽스처에서 터치 없이 약 5초를 기다린 결과 resident 좌표가 `(47.41, 68.39)`에서 `(58.98, 61.86)`으로 변했고 animation은 running이었다. 실제 엔진의 DOM 갱신·사용자 기기·설정은 재현하지 못했으므로 사용자 문제의 원인을 해결했다고 말할 수 없다.

## 후속 실행·우선순위

1. 원본 목업 보드/ZIP과 지침의 정확한 버전 확보, 0.6.14 실엔진 격리 서버를 띄워 홈·작업·시설/창고·의뢰·탐험·이야기·우편·주민/프로필·초대·설정·백업 화면을 같은 뷰포트에서 촬영. 화면별 차이표에 목업 위치, 구현 캡처, 에셋명, 누락 원인, 영향, 상태, 검증 경로를 적는다. 원본이 없으면 '판정 불가'로 둔다.
2. 실제 진입 경로별 상단바/전체화면을 분해하고 브라우저 보안 제약과 별도 진입점의 책임을 조사. 주민 무터치 30초·화면 갱신·포커스·모션 감소·지면 편집 상황을 기록해 재현한 후 수정한다.
3. 홈 모핑/터치 반응은 원본 이미지 보존, 기존 프로필 접근, 실제 방향·발 기준·감정위치·터치 영역·모션 감소를 함께 설계하고 전후 녹화와 사용성 검토.
4. 기능별 연결 목록 API와 엔진 호환을 검증하고 모델 선택을 먼저 완성. 이후 고정 활동 결과를 보존하면서 사건 기반 주민 편지 및 오류/재시도/중복/장기 저장을 구현.
5. 본문에서 분류한 경제·이야기·날씨·삽화 등 나머지 누락을 의존성 및 사용자 우선순위에 따라 별도 단위로 설계한다. 낡은 카탈로그 소개, 사용하지 않는 에셋, 폰트 및 목업 차이는 이 과정에서 개별 수정하고 생성물을 빌드로 재생성한다.
