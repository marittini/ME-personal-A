## 1. 구현 범위

| 계획서 | 구현 |
|---|---|
| §7.1 원본과 주민 분리 | 주민은 `residentId`, 원본은 `kind`(캐릭터·페르소나) + `sourceId`. 등록 때 서버가 원본을 **직접 읽어** 이름·설명·성격·상황과 원본 해시를 snapshot으로 보관한다. 클라이언트는 snapshot을 보낼 수 없다(보내면 `invalid_payload`) |
| §10 동일 주민 1명 | 한 세계에서 같은 원본은 한 주민. 명령 규칙과 세계 스키마 검사 두 곳에서 막는다. 두 탭이 동시에 등록해도 한 명만 생긴다 |
| §3 페르소나 독립 | 페르소나 주민은 주민일 뿐 플레이어가 아니다. 플레이어는 여전히 닉네임만 있다. 재구축 프롬프트에도 명시 |
| §7.1 재구축 | 원래 설정 ↔ 공방 세계 설정(200자) 비교, 수정, 변경 이력(최근 50개). 다시 제안은 엔진의 기본 언어 모델을 한 번 부르고 결과는 폼에만 채운다. 확정 전에는 아무것도 저장하지 않는다 |
| §3 시작 주민 | 세계당 한 번, 고른 주민은 영입된 상태가 된다. 다른 주민은 "초대 대기"(초대는 P3) |
| §7.1 페어 | **어느 두 주민이든**(캐릭터–페르소나, 캐릭터–캐릭터, 페르소나–페르소나, 2026-10-27 소유자 결정). 방향 없는 한 쌍으로 저장하고, 같은 두 주민은 한 행(보관 포함)이다. 한 주민이 여러 페어(A–B, A–C). 새 페어는 친밀도·편안함 0, 사건 없음(소급 기억·자동 연애 없음). 보관은 이별이 아니며 값을 그대로 두고 되돌릴 수 있다 |
| §8.1 주민 그림 | 사용자가 고른 PNG·정적 WebP만. 바이트 검사 → 디코더 검사 → WebP 95(투명 유지) → 전역 갤러리 → 내부 명령 `residents.setImage`로 세계에 연결. 저장 실패 시 새 갤러리 파일을 지우고 기존 그림 유지. 업로드 키 = 명령 ID라 재전송해도 두 번 저장되지 않는다. 원본 카드의 프로필 사진은 읽지도 쓰지도 않는다 |
| §8.1 배치 | 그림 크기 50–150% · 좌우 위치 ±50 · 기호 높이 ±50을 `placement`로 따로 저장. 그림 파일에 굽지 않는다. 홈 장면·카드·미리보기가 같은 값을 쓴다 |
| §8.1 이력 | 최근 3장 보관, 이전 그림으로 되돌리기. 밀려난 그림과 "그림 이력 정리"로 놓은 그림은 엔진이 다른 곳에서 쓰지 않는다고 할 때만 갤러리에서 지운다 |
| §6 백업 | 형식 2: WebP 파일(base64 + sha256)을 함께 담는다. 복원은 모든 참조가 파일로 채워졌는지, 해시가 맞는지 먼저 확인한 뒤 갤러리에 올려 **새 ID로 재매핑**한다. 중간에 실패하면 올린 파일을 지우고 세계를 만들지 않는다. 형식 1(P1 백업)도 읽는다 |
| §6 스키마 | 세계 schemaVersion 3. v1 → v2(주민·페어 빈 목록, 시작 주민 없음) → v3(캐릭터×페르소나 페어를 두 주민 한 쌍으로) 순차 마이그레이션. 실제 엔진에서 기존 v2 세계 36개가 모두 읽힘을 확인 |

새 명령: `residents.register`, `residents.update`, `residents.chooseStarter`, `residents.setImage`(서버 전용), `residents.restoreImage`,
`residents.setPlacement`, `residents.clearImageHistory`, `pairs.add`, `pairs.archive`, `pairs.restore`.
새 라우트: `GET /sources`, `GET /sources/preview`, `POST /rebuild-suggestion`, `POST /residents/image`(multipart).

## 5. 발견·결정 사항

- **한글 입력과 다시 그리기**: 입력할 때마다 화면을 다시 그리면 한글 조합이 깨진다. 공방 세계 설정은 다시 그리지 않고 값만 기억하고(`Store.remember`), 검색은 조합이 끝난 뒤 잠시 기다렸다가 적용한다. 다시 그릴 때 커서 위치도 지킨다.
- **알림이 버튼을 가림**: 아래 알림이 마지막 버튼(주민 불러오기)을 덮어 브라우저 흐름이 실패했다. 안내 알림은 4초 뒤 사라지고, 알림이 있는 동안 화면 아래에 여백을 둔다. 오류 알림은 닫을 때까지 남는다.
- **동시에 같은 원본 등록**: 가짜 저장소(엔진처럼 트랜잭션을 하나씩 실행)에서 두 요청 중 정확히 하나만 성공함을 확인했다.
- **다시 제안은 동기 요청**: 엔진의 에이전트 호출 제한 시간 안에서 한 번 부른다. ponytail: 재개 가능한 생성 상태(`POST /generation`)는 그것이 꼭 필요한 이야기 단계(P4)에서 들인다.
- **페어 종류(변경)**: 처음엔 계획서대로 캐릭터 × 페르소나만 허용했으나, 소유자 결정으로 어느 두 주민이든 페어가 되도록 바꿨다(스키마 v3).
- **엔진 위 떠 있는 버튼**: 엔진의 미디어 버튼이 여전히 패키지 화면 왼쪽 위를 가린다(P0부터 기록, 엔진 쪽 문제).

## 6. 화면 스타일 (2026-10-27 소유자 피드백 반영)

목업의 동화풍에 맞춰 스타일을 다시 정했다: 모든 카드·버튼·탭·입력·표·막대·토글에 **짙은 갈색(#4b2e1a) 약 3px 외곽선**,
들어 올린 요소 아래 납작한 그림자(번짐 없음), 평평한 색 채움. 1px 안팎의 얇은 선, 점선 안쪽 테두리, 색이 번지는 그라데이션(버튼·간판·동전·배경)을
모두 없앴다. 배경은 평평한 덤불 실루엣과 굵은 이음매의 나무 판자, 홈 장면 그림도 같은 외곽선의 평면 그림으로 바꿨다. 토큰은 `styles.ts`의
`--ink`(선 색) · `--line`(선 굵기) · `--drop`(그림자) 세 개로 모아, 에셋이 들어오는 P5에서 한 곳만 고치면 된다. 둥근 동화풍 글꼴은
라이선스·패키지 포함 조건을 확인해야 하므로 P5 에셋과 함께 들인다(지금은 시스템 글꼴).
