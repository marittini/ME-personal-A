# 주민·관계·등록·관리 화면 정리 — 0.6.19

## 변경

- 주민의 텍스트 목록을 목업의 두 열 그림 카드로 복원. 그림/이름/종류/분야/영입 상태를 함께 표시한다. 실제 주민 그림은 계속 사용자 업로드를 사용한다. 없는 그림은 실루엣과 `그림 없음`으로 표시한다.
- 주민 목록과 선택 상세를 같은 화면으로 통합. 페이지별 2명, 검색·종류·영입 필터는 유지한다. 기본 상세는 현재 페이지의 첫 주민, 클릭하면 같은 페이지의 선택 주민으로 변경한다. 현재 필터/페이지 밖의 주민을 상세로 잘못 표시하지 않는다.
- 외부 경로에서 특정 주민을 열 때 검색/종류/영입 필터를 초기화하고 정렬된 전체 목록에서 그 주민의 페이지를 계산한다. 이전 detailOpen 값은 화면/스크롤 분기에 쓰지 않는다. 같은 페이지의 선택 변경은 목록 스크롤을 초기화하지 않는다.
- 관계: 공유 주민 초상 크기 제한, 이름표 겹침 해소, 긴 이름·관계 표기 줄바꿈, 좁은 화면의 세로 배치와 행동 버튼 터치 영역. 기억/지침 버튼에 관리 그림 연결.
- 등록: 단계 표시는 동일한 세 열에 숫자/글자를 중앙 정렬. 첫 자료 선택은 그림 관리 아이콘을 사용. 업로드 안내·대상 이름표의 줄바꿈/중앙 정렬. 이전·다음은 한 줄로 유지하고, 한 명만 남은 카드 페이지는 가운데 배치.
- 관리: 주민 그림·AI 지침·기억·저장/백업의 네 행을 공통 크기·간격·이동 화살표로 통일. 생성한 그림을 각 역할에 연결.

## 추가 그림

`ui/manage-portrait.webp`, `manage-guidelines.webp`, `manage-memory.webp`, `manage-backup.webp`를 내장 이미지 생성으로 개별 제작했다. 각각 그림 액자·잎 책갈피 책·기억 등불·문서 보관함을 표현한다. 작은 화면용 단순한 형태, 갈색 윤곽과 크림/청록/목재 색감, 투명 배경, 질감·글자 없음을 요청했다. 128×128 WebP로 인코딩. 원본 PNG는 작업공간 generated_images에 보존하고 manifest source.original에 이름을 기록했다. 총 100개 에셋이다. 새 주민 캐릭터를 만들거나 기존 카드/페르소나의 초상을 가져오지 않았다.

## 검증

- strict 타입검사, 전체 forest-workshop 회귀, 에셋 경로·수량·바이트·해시·패키지 목록, 정적 검사, 빌드/카탈로그/로케일/릴리스노트 검사.
- 주민 브라우저: 목록 유지·페이지 이동·선택 상태·그림/프로필/관계 버튼의 대상 주민, 실제 resident action으로 검색 필터가 있던 상태에서 다른 페이지 주민을 열 때 올바른 페이지/선택으로 이동하는지 확인.
- 관계: 320px·글자 22px에서 가로 넘침과 기억/지침의 대상 페어 확인.
- 등록: 기존 단계/초안/자료 페이지/시작 주민 선택 흐름, 320px·22px에서 가로 넘침과 이동 버튼 표시 확인.
- 관리: 실제 아이콘 바이트 로딩, 관리 행 4개의 표시 및 지침/기억/백업 진입. 기존 프로필·날씨·자동 읽기 설정 흐름 유지.
- 주민의 기존 세로 높이 고정 검사는 제거하고 스크롤로 하단 행동에 도달하는지 검사한다. 큰 글자를 줄여 한 화면에 억지로 맞추지 않는다.
- 브라우저는 모의 세계/주민 및 실제 패키지 에셋으로 실행. 실제 Android와 사용자 서버 설치/업데이트는 미검증. 사용자 업로드 그림의 모든 비율/크기를 이번에 다시 확인한 것은 아니다.
- 캡처: `/workspace/forest-ux-review/residents-art-{390,320}.png`, `relations-art-320.png`, `register-art-320.png`, `management-art.png`. 모의 주민에 그림이 없으므로 실루엣으로 표시한다.

## 남은 범위

기억/지침의 상세 표현과 기본 선택기, 실제 사용자 데이터의 긴 이름·큰 그림·많은 관계, 모든 화면의 빈/로딩/오류 상태를 이어서 검수한다. 생성 편지·현실 날씨·지침 이력 등 별도 기능을 구현한 것으로 취급하지 않는다.
