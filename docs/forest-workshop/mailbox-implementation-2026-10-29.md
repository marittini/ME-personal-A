# 우편함 초기 구현 — 0.6.12

AI 지침 PR #15 위의 후속 구현이다. 홈 우편 아이콘에서 받은 편지/보관함과 본문을 열고 읽음·보관/받은 편지로 이동을 처리한다. 발신인은 주민을 가장하지 않는 ‘공방 안내’이며 환영 편지 하나를 고정 내용으로 제공한다. 만료·보상·자동 모델 호출·삭제는 없다. 새 세계와 기존 세계 변환에 같은 고정 사건 ID를 사용해 중복되지 않는다.

schema 9→10에 우편함을 추가한다. 새 형식으로 저장한 세계는 이전 패키지에서 열 수 없다. 읽음/보관은 기존 세계 명령의 트랜잭션·revision·commandId 체계를 사용하며 본문 편집 명령은 없다. 첫 읽음 시각을 보존한다. 고정 편지의 작은 본문과 상태는 세계 문서에 함께 저장해 원자성과 기존 백업 경로를 사용한다. 현재 상한은 편지 200개, 본문 1,000자다. 이는 초기 고정 편지용 단순 구현이며 긴 생성 편지를 붙이기 전에 별도 본문 문서·페이지 조회·백업 지원으로 확장해야 한다.

검증: 실제 command service와 FakeHost persistence에서 세계 생성 재시도·읽음 명령 재시도·보관·재화 불변·별도 세계로 백업 복원 및 복원 재시도·기존 형식 변환·중복 편지 거부를 검사했다. 브라우저에서 받은 편지→본문→보관함→받은 편지 복귀가 통과했다. 엄격 타입·format/lint·회귀 12개·카탈로그 lane/locale/ZIP 해시/릴리스 노트 검증도 통과했다.

격리 엔진 2.5.1에 0.6.12 ZIP을 fixture로 주입해 새 테스트 세계를 만들고 [320px 우편함 화면](mobile-review/mailbox-engine-320.png)을 확인했다. 환영 편지를 읽고 보관한 뒤 새 브라우저로 같은 세계를 열어 안 읽은 수 0개와 보관함의 읽은 편지 1개가 유지됨을 확인했다. 기존 세계 변환과 백업 복원은 회귀 환경에서 검사했으며 실엔진 사용자 데이터에서는 검사하지 않았다.

남은 범위: 주민 편지의 명시적 모델 생성·기억/지침 적용·조사/순찰 완료 트리거, 별도 본문 저장·cursor 조회, 정상 카탈로그 설치/업데이트·Android 검증은 미완료다. 본 PR은 전체 우편 생성 시스템의 완료가 아니다.
